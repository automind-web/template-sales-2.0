# AI Sales Corp: публикация в ChatGPT Sites

Инструкция для ChatGPT Sites и владельца сайта. По ней проект собирается, база создаётся из миграций и сайт публикуется без дополнительных вопросов.

## 1. Что за проект

Шаблонный корпоративный сайт продаж. Один код обслуживает разные компании, отличия задаются настройками (`config/company.ts`) и данными в БД. Разделы: Обучение, CRM, KPI, Статистика, WhatsApp Studio. Вход только по собственному логину и паролю сайта.

| Часть | Решение |
|---|---|
| Фронтенд | React 19, Tailwind CSS 4, компоненты в стиле shadcn/ui (`components/ui`) |
| Сервер | Next.js App Router на vinext (Vite), один Worker |
| БД | Cloudflare D1 (SQLite), привязка `DB` |
| Файлы | Cloudflare R2, привязка `BUCKET`; метаданные файлов в D1 |
| ORM | Drizzle ORM + Drizzle Kit |
| Node.js | 22.13 или новее |

## 2. Сборка

| Шаг | Команда |
|---|---|
| Установка зависимостей (Linux-сборщик Sites) | `npm run install:ci` (локально хватит `npm ci`) |
| Сборка и проверка артефакта | `npm run build` |

`npm run build` выполняет проверку типов, `vinext build` и проверку артефакта. Результат:

| Путь | Что это |
|---|---|
| `dist/server/index.js` | ES-модуль Worker'а, `export default { fetch(request, env, ctx) }` |
| `dist/client/` | статические файлы |
| `dist/.openai/hosting.json` | привязки D1/R2 |
| `dist/.openai/drizzle/` | история миграций для применения перед публикацией |

Express, собственные порты, постоянные TCP-соединения, Postgres/MySQL/Supabase/Vercel не используются. Фоновых процессов нет.

## 3. Привязки (`.openai/hosting.json`)

```json
{
  "d1": "DB",
  "r2": "BUCKET"
}
```

Секретов в файле нет. `project_id` Sites добавляет сам после создания проекта.

> **Сверьте формат.** Формат взят из публичного стартового шаблона Sites на vinext (`d1-r2-starter-openai`, генератор `j-256/d1-r2-starter-factory`). Официальная документация Sites из среды разработки была недоступна. Если в вашем шаблоне поля называются иначе, поправьте только этот файл: код читает привязки как `env.DB` и `env.BUCKET`.

## 4. База данных и миграции

- Миграции лежат в `drizzle/`, порядок задан журналом `drizzle/meta/_journal.json`: `0000_init.sql` (вход, филиалы, роли), `0001_training.sql` (обучение), `0002_crm.sql` (лиды, история, операции), `0003_kpi.sql` (версии методики KPI), `0004_whatsapp.sql` (агенты, материалы, номера, журнал сообщений).
- При сборке они копируются в `dist/.openai/drizzle/`. Sites применяет их к D1 до того, как новая версия получит трафик.
- Чистый запуск ничего не наполняет: нет компаний, сотрудников, клиентов и сделок. Компания создаётся, когда владелец выпускает ссылку активации директора.
- **Применённые миграции не правятся.** Контрольные суммы записаны в `db/migration-lock.json`, тест `test/migrations.test.ts` падает, если файл изменён. Порядок изменения схемы:
  1. изменить `db/schema.ts`;
  2. `npm run db:generate -- --name <описание>` — новый файл в `drizzle/`;
  3. проверить SQL, при необходимости дописать перенос данных;
  4. `npm run db:lock` — зафиксировать контрольную сумму новой миграции.
- Откат версии в Sites возвращает код, но не данные. Поэтому каждая миграция только добавляет: новые таблицы и столбцы с значениями по умолчанию. Старый код продолжает работать на новой схеме.

## 5. Секреты (настройки сайта)

Значения вносит владелец в настройках сайта Sites. В репозитории есть только имена (`.env.example`). Код читает их из окружения Worker'а (`env.ИМЯ`) только на сервере. В ответы, клиентские журналы и кэш они не попадают.

| Секрет | Нужен с этапа | Назначение |
|---|---|---|
| `OWNER_ACTIVATION_CODE` | 1 | Код владельца для выпуска ссылки активации первого директора. Длинная случайная строка, 32+ символа |
| `INTEGRATION_TOKEN` | 2 | Токен для загрузки утверждённых материалов обучения через защищённый интерфейс интеграции |
| `OPENAI_API_KEY` | 7 | Ключ модели для агента WhatsApp Studio |
| `WHAPI_TOKEN` | 7 | Токен Whapi для подключения рабочего номера WhatsApp |

## 6. Доступ к сайту

- В настройках доступа Sites сайт должен быть **открыт для всех** (публичный). Иначе посетитель без аккаунта ChatGPT не увидит форму входа.
- «Вход через ChatGPT» и любой внешний или социальный вход не используются. Пути `/signin-with-chatgpt` и заголовки `oai-authenticated-*` приложение не читает.
- Права проверяет сервер приложения на каждом запросе: роль, филиал и допуск читаются из D1, сессия — из HttpOnly-cookie.

## 7. Активация первого директора

1. Задайте секрет `OWNER_ACTIVATION_CODE` и опубликуйте сайт.
2. Откройте `https://<адрес-сайта>/owner` («Активация компании»).
3. Введите секрет владельца, название компании и срок действия в часах (1–168, по умолчанию 72), нажмите «Выпустить приглашение».
4. Передайте ссылку `/activate/…` директору по защищённому каналу. Ссылка:
   - одноразовая: гаснет после успешной регистрации;
   - действует заданное число часов (по умолчанию 72 — `activationLinkTtlHours` в `config/company.ts`);
   - не гаснет при открытии и при ошибках в форме.
5. Директор задаёт имя, логин и пароль и сразу попадает в «Настройки системы» → «Филиалы». Там же, во вкладках «Участники» и «Приглашения», он приглашает руководителей и сотрудников.

Защита: попытки ввода кода владельца ограничены (5 за 15 минут с одного IP). Код сравнивается за постоянное время. Хранится только SHA-256 от токена ссылки, сам токен в БД не хранится.

Если директор потерял пароль, второй директор выдаёт ему код сброса, либо владелец выпускает новую ссылку активации, и директор создаёт новую учётную запись.

## 8. Загрузка материалов обучения (интерфейс интеграции)

Утверждённые редакции курсов загружаются только через серверную точку входа с секретом `INTEGRATION_TOKEN`. Каждая редакция сохраняется отдельной неизменяемой версией. Сотрудник, начавший тест, завершает его по своей версии; новая редакция применяется со следующей попытки.

| Метод и путь | Назначение |
|---|---|
| `POST /api/integration/training/files` | Файл материала в R2 (multipart: `file`, `courseKey`, необязательно `courseTitle`). Ответ: `fileId`. До 25 МБ |
| `POST /api/integration/training/courses/{courseKey}/versions` | Новая утверждённая редакция курса (JSON, см. ниже) |
| `GET /api/integration/training/courses` | Какие курсы и версии уже загружены |

Заголовок: `Authorization: Bearer <INTEGRATION_TOKEN>`. Ключ курса — латиница в нижнем регистре, цифры, `.`, `_`, `-`. Ключ из правил допуска (по умолчанию `sales-basics`) связывает курс с допуском к CRM.

```bash
curl -X POST "https://<адрес-сайта>/api/integration/training/files" \
  -H "Authorization: Bearer $INTEGRATION_TOKEN" \
  -F courseKey=sales-basics -F "file=@pamyatka.pdf;type=application/pdf"
```

```bash
curl -X POST "https://<адрес-сайта>/api/integration/training/courses/sales-basics/versions" \
  -H "Authorization: Bearer $INTEGRATION_TOKEN" -H "Content-Type: application/json" \
  --data @sales-basics-rev-1.json
```

Формат редакции:

```json
{
  "approved": true,
  "externalRef": "rev-2026-11-25",
  "title": "Основы продаж",
  "description": "Обязательный курс для работы в CRM",
  "lessons": [
    { "key": "intro", "title": "Наш клиент", "body": "Абзацы через пустую строку.\n\n- пункт списка", "durationMinutes": 10, "fileIds": ["<fileId>"] }
  ],
  "test": {
    "passPercent": 80,
    "questions": [
      { "key": "q1", "text": "Когда перезвонить новому клиенту?", "kind": "single",
        "options": [{ "key": "a", "text": "В течение часа" }, { "key": "b", "text": "Через неделю" }],
        "correct": ["a"] }
    ]
  }
}
```

Правила:
- `approved: true` обязателен — черновики не принимаются.
- `externalRef` — идентификатор редакции у вас. Повторная доставка с тем же `externalRef` и тем же содержимым возвращает существующую версию (`created: false`); с другим содержимым — ошибка 409: утверждённая версия не изменяется.
- `kind`: `single` (ровно один правильный вариант) или `multiple` (засчитывается только точное совпадение набора). Результат округляется вниз.
- Правильные ответы хранятся на сервере и сотруднику не передаются.
- Файл доступен только тем, кому назначен его курс; R2-объект хранит содержимое, D1 — метаданные.

Назначение и допуск:
- Курс из правила допуска назначается сотрудникам автоматически. Дополнительно руководитель назначает курсы своему филиалу или сотруднику, директор — также всей компании.
- Правила допуска задаёт директор: «Обучение» → «Правила допуска». Правила филиала заменяют общие для этого филиала. Допуск выдаётся автоматически, когда выполнены все правила; вручную его можно выдать или снять флажком «допущен» в «Настройки системы» → «Участники».

## 9. Проверка перед публикацией

```bash
npm test                          # серверные сценарии на SQLite (без сборки)
npm run lint
npm run build                     # typecheck + vinext build + проверка артефакта
npm run test:artifact             # собранный Worker в Miniflare: миграции с нуля, вход, cookie
```

Браузерные сценарии (ПК и iPhone): `npm run dev` на чистой БД, затем один из `node e2e/stage1.mjs`, `stage2.mjs`, `stage3.mjs`, `stage5.mjs`, `stage7.mjs` или полный путь приёмки `node e2e/acceptance.mjs` (нужен playwright с Chromium; перед каждым сценарием — чистая БД: удалите `.wrangler/state`). Локальные секреты для `npm run dev` берутся из `.dev.vars` (см. `.env.example`). Локальная D1 в `.wrangler/state`. В режиме разработки миграции применяются автоматически, в рабочей сборке это делает Sites.

## 11. Ограничения платформы

- Запуск по расписанию: в `worker/index.ts` есть обработчик `scheduled` — коротко повторяет неотправленные ответы WhatsApp. Если расписание в Sites недоступно, ничего не теряется: повтор идёт при следующем входящем сообщении и по кнопке «Повторить неотправленные» в WhatsApp Studio.
- Долгих фоновых процессов нет: ответ агента готовится в продлении запроса (`ctx.waitUntil`), очередь — таблица `wa_messages`.
- Платёжные карточные данные не обрабатываются.

## 12. WhatsApp Studio

Раздел доступен директору и руководителю филиала. Всё настраивается для каждого филиала отдельно (директор выбирает филиал в шапке).

1. **Агент.** «Создать агента из базового» копирует имя и инструкцию из `config/company.ts` (`whatsappAgent`). Инструкцию филиал правит сам.
2. **Разрешённые материалы.** Текст вручную или «Из курса обучения» (тексты уроков последней утверждённой редакции; вопросы и ответы теста агенту не передаются). Агент отвечает только по ним; если ответа нет — обещает передать вопрос менеджеру. Данные компании (сотрудники, клиенты, сделки, суммы) в запрос к модели не попадают.
3. **Тестовый диалог.** Чат в стиле WhatsApp: тот же агент и материалы, ничего не отправляется. Результат последней проверки виден в карточке агента.
4. **Модель.** С секретом `OPENAI_API_KEY` отвечает модель OpenAI (Chat Completions, модель выбирает директор в «Настройки системы» → «Процесс»). Без ключа или при сбое модели агент работает офлайн: отвечает подходящим абзацем материалов или передачей менеджеру. Экран показывает, в каком режиме работает агент.
5. **Рабочий номер.** Нужен секрет `WHAPI_TOKEN` (токен канала Whapi, на котором номер авторизован по QR). «Подключить номер» создаёт случайный секрет webhook, сохраняет в Whapi адрес `https://<сайт>/api/whatsapp/webhook/<секрет>` (событие `messages`) и проверяет реальное состояние канала. В БД хранится только SHA-256 секрета; при отключении адрес перестаёт работать. Один токен Whapi — один номер, поэтому номер работает в одном филиале.
6. **Состояние и восстановление.** Состояние номера показано отдельно от статуса подключения: «авторизован», «не авторизован (QR)», «запускается», «токен отклонён», «Whapi недоступен», «токен не задан» — у каждого написан способ восстановления.
7. **Входящие.** Webhook принимает только личные текстовые сообщения клиентов (группы и свои сообщения пропускаются). Повторная доставка того же сообщения не создаёт дубль. Незнакомый номер становится новым лидом филиала (источник «WhatsApp», без ответственного) и получает только ответ агента. Журнал сообщений со ссылками на лиды — во вкладке «Журнал сообщений».

| Метод и путь | Назначение |
|---|---|
| `POST /api/whatsapp/webhook/{секрет}` | Входящие сообщения Whapi (без cookie и CSRF; секрет в адресе, сверка по хэшу; 600 запросов в минуту с IP) |

## 13. Приёмка

| Пункт | Значение |
|---|---|
| Версия сборки | 0.1.0 (`package.json`) |
| Версия схемы | `0004_whatsapp` (5 миграций, контрольные суммы в `db/migration-lock.json`) |
| Активация директора | Секрет `OWNER_ACTIVATION_CODE` → страница `/owner` → одноразовая ссылка `/activate/…` (раздел 7) |
| Серверные сценарии | `npm test`: 29 из 29 (доступ и изоляция, обучение и допуск, CRM и конфликты, KPI = статистика, WhatsApp с поддельными Whapi и OpenAI) |
| Браузерные сценарии | `e2e/acceptance.mjs` и `e2e/stage1–7.mjs` на ПК и iPhone 13: пройдены, ошибок в консоли нет |
| Проверка артефакта | `npm run build` и `npm run test:artifact` (собранный Worker в Miniflare, миграции с нуля) |
| WhatsApp | Сборка готова к подключению. **Реальный обмен сообщениями через подключённый номер не подтверждён**: в среде разработки нет `WHAPI_TOKEN` и выхода в сеть к Whapi. Проверено: webhook, дедупликация, создание лида, отправка и повтор — на поддельном Whapi; тестовый диалог — офлайн и с поддельной моделью |

Полный путь приёмки (`e2e/acceptance.mjs`): владелец выпускает ссылку → директор регистрируется и создаёт филиал → приглашает руководителя → руководитель приглашает сотрудника → курс приходит через интеграцию → сотрудник на телефоне проходит урок и тест и автоматически получает допуск → создаёт лид и переводит его в «Контакт» → руководитель на ПК видит лид в статистике и открывает исходную сделку с историей → директор на телефоне видит тот же показатель → руководитель другого филиала лид не видит.

Чтобы подтвердить WhatsApp на рабочем сайте: задайте `WHAPI_TOKEN` (и при желании `OPENAI_API_KEY`), в WhatsApp Studio создайте агента, добавьте материалы, нажмите «Подключить номер», дождитесь состояния «Номер авторизован» и напишите на номер с другого телефона. В журнале появятся входящее и ответ агента, в CRM — новый лид.
