# AI Sales Corp: публикация в ChatGPT Sites

Инструкция для ChatGPT Sites и владельца сайта. По ней проект собирается, база создаётся из миграций и сайт публикуется без дополнительных вопросов.

## 1. Что за проект

Шаблонный корпоративный сайт продаж. Один код обслуживает разные компании, отличия задаются настройками (`config/company.ts`) и данными в БД. Разделы: Обучение, CRM, KPI, Статистика, WhatsApp Studio. Вход только по собственному логину и паролю сайта.

| Часть | Решение |
|---|---|
| Фронтенд | React 19, Tailwind CSS 4, компоненты в стиле shadcn/ui (`components/ui`) |
| Сервер | Next.js App Router на vinext (Vite), один Worker |
| БД | Cloudflare D1 (SQLite), привязка `DB` |
| Файлы | Cloudflare R2, привязка `BUCKET`; метаданные файлов в D1 |
| ORM | Drizzle ORM + Drizzle Kit |
| Node.js | 22.13 или новее |

## 2. Сборка

| Шаг | Команда |
|---|---|
| Установка зависимостей (Linux-сборщик Sites) | `npm run install:ci` (локально хватит `npm ci`) |
| Сборка и проверка артефакта | `npm run build` |

`npm run build` выполняет проверку типов, `vinext build` и проверку артефакта. Результат:

| Путь | Что это |
|---|---|
| `dist/server/index.js` | ES-модуль Worker'а, `export default { fetch(request, env, ctx) }` |
| `dist/client/` | статические файлы |
| `dist/.openai/hosting.json` | привязки D1/R2 |
| `dist/.openai/drizzle/` | история миграций для применения перед публикацией |

Express, собственные порты, постоянные TCP-соединения, Postgres/MySQL/Supabase/Vercel не используются. Фоновых процессов нет.

## 3. Привязки (`.openai/hosting.json`)

```json
{
  "d1": "DB",
  "r2": "BUCKET"
}
```

Секретов в файле нет. `project_id` Sites добавляет сам после создания проекта.

> **Сверьте формат.** Формат взят из публичного стартового шаблона Sites на vinext (`d1-r2-starter-openai`, генератор `j-256/d1-r2-starter-factory`). Официальная документация Sites из среды разработки была недоступна. Если в вашем шаблоне поля называются иначе, поправьте только этот файл: код читает привязки как `env.DB` и `env.BUCKET`.

## 4. База данных и миграции

- Миграции лежат в `drizzle/`, порядок задан журналом `drizzle/meta/_journal.json`: `0000_init.sql` (вход, филиалы, роли), `0001_training.sql` (обучение), `0002_crm.sql` (лиды, история, операции), `0003_kpi.sql` (версии методики KPI), `0004_whatsapp.sql` (первая версия WhatsApp), `0005_whatsapp_studio.sql` (WhatsApp Studio: агенты, ключи, база знаний, собеседники, очередь ответов), `0006_remove_old_whatsapp.sql` (удаляет таблицы первой версии; рабочих данных в них не было), `0007_access_and_kpi.sql` (рабочие роли, рабочая роль сотрудника, дата начала действия методики KPI).
- При сборке они копируются в `dist/.openai/drizzle/`. Sites применяет их к D1 до того, как новая версия получит трафик.
- Чистый запуск ничего не наполняет: нет компаний, сотрудников, клиентов и сделок. Компания создаётся, когда владелец выпускает ссылку активации директора.
- **Применённые миграции не правятся.** Контрольные суммы записаны в `db/migration-lock.json`, тест `test/migrations.test.ts` падает, если файл изменён. Порядок изменения схемы:
  1. изменить `db/schema.ts`;
  2. `npm run db:generate -- --name <описание>` — новый файл в `drizzle/`;
  3. проверить SQL, при необходимости дописать перенос данных;
  4. `npm run db:lock` — зафиксировать контрольную сумму новой миграции.
- Откат версии в Sites возвращает код, но не данные. Поэтому каждая миграция только добавляет: новые таблицы и столбцы с значениями по умолчанию. Старый код продолжает работать на новой схеме.

## 5. Секреты и ключи

В настройках сайта Sites нужен только код владельца. Остальное директор вводит на самом сайте.

| Значение | Где задаётся | Назначение |
|---|---|---|
| `OWNER_ACTIVATION_CODE` | настройки сайта Sites, **обязательно** | Код владельца для выпуска ссылки активации первого директора. Длинная случайная строка, 32+ символа |
| Ключ WhatsApp (Whapi) | сайт → WhatsApp Studio (только директор) | Подключение рабочего номера |
| Ключ ChatGPT или Gemini | сайт → WhatsApp Studio (только директор) | Ответы агента |
| `MASTER_KEY` | настройки сайта, необязательно | Свой ключ шифрования сохранённых ключей (32 байта, base64). Без него сайт создаёт ключ сам при первом сохранении и хранит его на сервере. Не меняйте после первого использования |
| `INTEGRATION_TOKEN` | настройки сайта, необязательно | Загрузка программы обучения из внешней системы (раздел 8). Обычно не нужен: программа правится на сайте |

Ключи, введённые на сайте, шифруются на сервере (AES-GCM) и в браузер не возвращаются — на экране видно только «Сохранён». В журналы и общий кэш они не попадают.

## 6. Доступ к сайту

- В настройках доступа Sites сайт должен быть **открыт для всех** (публичный). Иначе посетитель без аккаунта ChatGPT не увидит форму входа.
- «Вход через ChatGPT» и любой внешний или социальный вход не используются. Пути `/signin-with-chatgpt` и заголовки `oai-authenticated-*` приложение не читает.
- Права проверяет сервер приложения на каждом запросе: роль, филиал и допуск читаются из D1, сессия — из HttpOnly-cookie.

## 7. Активация первого директора

1. Задайте секрет `OWNER_ACTIVATION_CODE` и опубликуйте сайт.
2. Откройте `https://<адрес-сайта>/owner` («Активация компании»).
3. Введите код владельца, название компании и срок действия в часах (1–168, по умолчанию 72), нажмите «Выпустить приглашение».
4. Передайте ссылку `/activate/…` директору по защищённому каналу. Ссылка:
   - одноразовая: гаснет после успешной регистрации;
   - действует заданное число часов (по умолчанию 72 — `activationLinkTtlHours` в `config/company.ts`);
   - не гаснет при открытии и при ошибках в форме.
5. Директор задаёт имя, логин и пароль и попадает на главную с «Первыми шагами»: создать филиал, пригласить людей, проверить обучение, подключить WhatsApp. Там же, во вкладках «Участники» и «Приглашения», он приглашает руководителей и сотрудников.

Защита: попытки ввода кода владельца ограничены (5 за 15 минут с одного IP). Код сравнивается за постоянное время. Хранится только SHA-256 от токена ссылки, сам токен в БД не хранится.

**Первичная активация — один раз.** Пока директора нет, владелец может выпустить ссылку повторно; новая ссылка отключает прежнюю неиспользованную. Как только директор зарегистрировался, `/owner` показывает «Компания уже активирована», новые ссылки не выпускаются, а неиспользованная ссылка уже не сработает (проверка на сервере и в самом запросе к БД).

Если директор потерял пароль: второй директор выдаёт ему код сброса в «Сотрудниках», либо владелец на `/owner` вводит код владельца и логин директора и получает код восстановления (24 часа). Директор вводит его на странице «Забыли пароль?». Действие записывается в журнал прав.

### Приглашения и журнал прав

- Приглашение можно **перевыпустить** («Настройки системы» → «Приглашения» → «Перевыпустить»): новая ссылка с той же ролью и филиалом, старая сразу перестаёт работать. Использованное приглашение не перевыпускается.
- **Журнал прав** («Настройки системы» → «Журнал прав»): кто, когда и что изменил — выпуск, перевыпуск, отзыв и использование приглашений, смена роли, филиала и рабочей роли, отключение, коды восстановления и смена пароля, отметка «Прошёл обучение», рабочие роли. Директор видит всю компанию (или выбранный филиал), руководитель — свой филиал.

## 8. Обучение

Одна программа обучения для новых сотрудников. При первом обращении создаётся стартовая программа из `config/company.ts` (`training`): 3 урока и 5 вопросов о работе с заявками.

- **Директор** правит программу на сайте: «Обучение» → «Программа» — название, уроки, вопросы с правильными ответами, проходной балл. Каждое сохранение — новая неизменяемая версия. Начатый тест завершается по своей версии, новая применяется со следующей попытки.
- **Новый сотрудник** после регистрации видит только обучение: уроки → тест → рабочее место. CRM и KPI в меню показаны с замком. Когда тест сдан на проходной балл, рабочее место открывается само.
- **Руководитель филиала и директор** видят прогресс команды («Обучение» → «Сотрудники») и могут поставить отметку **«Прошёл обучение»** — там же или в «Настройки системы» → «Сотрудники». Рабочее место открывается сразу.

Необязательно: программу можно загружать из внешней системы с секретом `INTEGRATION_TOKEN` (`POST /api/integration/training/courses/sales-basics/versions`, JSON с `approved: true`, `lessons`, `test`; файлы уроков — `POST /api/integration/training/files` в R2). Правильные ответы хранятся на сервере и сотруднику не передаются.

## 8а. KPI

- **Методика** («KPI» → «Конструктор»): показатели с формулой из блоков (показатели, числа, действия). Блоки можно **перетаскивать** мышью или переставлять через меню блока. Каждое сохранение — новая версия; действует после утверждения.
- **Для кого:** компания, филиал или **отдельный сотрудник**. Для сотрудника берётся его формула, иначе формула филиала, иначе компании.
- **«Действует с»** — дата начала действия версии. До этой даты отчёт считается по прежней версии; без даты версия действует с момента утверждения.
- **«Предпросмотр расчёта»** — расчёт черновика за текущий месяц по каждому человеку, ничего не сохраняется.
- **«Скопировать сотрудникам»** — та же формула сразу нескольким сотрудникам (отдельная утверждённая версия каждому) с общей датой начала.
- **Вкладка «Прогноз»** — сколько дней периода прошло, факт сейчас, прогноз к концу периода и план с отметкой «Успевает / Под угрозой / Не успевает». Потоковые показатели (заявки, сделки, суммы) пересчитываются пропорционально прошедшим дням, текущие остатки (открытые заявки, просроченные контакты) берутся как есть.

## 9. Проверка перед публикацией

```bash

npm run lint
npm run build                     # typecheck + vinext build + проверка артефакта
npm run test:artifact             # собранный Worker в Miniflare: миграции с нуля, вход, cookie
```

Браузерные сценарии (ПК и iPhone): `npm run dev` на чистой БД, затем один из `node e2e/stage1.mjs`, `stage2.mjs`, `stage3.mjs`, `stage5.mjs`, `stage7.mjs`, `stage8.mjs` (доступы и KPI) или полный путь приёмки `node e2e/acceptance.mjs` (нужен playwright с Chromium; перед каждым сценарием — чистая БД: удалите `.wrangler/state`). Локальные секреты для `npm run dev` берутся из `.dev.vars` (см. `.env.example`). Локальная D1 в `.wrangler/state`. В режиме разработки миграции применяются автоматически, в рабочей сборке это делает Sites.

## 11. Ограничения платформы

- Запуск по расписанию: в `worker/index.ts` есть обработчик `scheduled` — коротко обрабатывает очередь ответов WhatsApp. Если расписание в Sites недоступно, ничего не теряется: ответы готовятся при приёме сообщений, а Whapi повторяет доставку, пока ответ в очереди.
- Долгих фоновых процессов нет: очередь ответов хранится в D1 (`jobs`, `outbox`).
- Платёжные карточные данные не обрабатываются.

## 12. WhatsApp Studio

Студия перенесена из шаблона [WhatsApp Agent Studio](https://github.com/automind-web/whatsapp-agent-studio-template) (движок `server/wa/*.mjs`, интерфейс `components/wa-studio/`) и встроена в систему: вход и права — общие, стили — в оформлении системы, тексты — без технических терминов. Доступна только директору.

1. **Агент.** «Создать агента» — с универсальной стартовой инструкцией (`basePrompt` в `server/wa/store.mjs`): вежливый консультант компании, короткие ответы, факты только из базы знаний, один уточняющий вопрос, передача менеджеру, без выдуманных скидок и подтверждений оплаты. Название компании подставляется само.
2. **Ключи.** Ключ WhatsApp из кабинета Whapi и ключ ChatGPT или Gemini вводятся в карточке «Подключение»; «Уровень ответов» — выбор модели (экономичная, универсальная, для сложных задач).
3. **База знаний.** Файлы PDF, DOCX, TXT, MD, CSV, JSON до 15 МБ; агент отвечает по найденным фрагментам.
4. **Проверка.** Тестовый диалог (текст и голосовые) — тот же агент и база знаний, клиенту ничего не отправляется.
5. **Включение.** «Включить агента» проверяет номер в Whapi и сохраняет в Whapi адрес приёма сообщений `https://<сайт>/api/wa/webhooks/whapi/<агент>` с секретным заголовком. Работает только на опубликованном сайте (https).
6. **Заявки.** Новый собеседник (личный чат) становится заявкой в CRM выбранного филиала: источник «WhatsApp», без ответственного. Повторная доставка сообщения ничего не дублирует. Из списка собеседников можно открыть заявку.
7. **Собеседники.** История переписки, запрет ответов, возврат диалога агенту после ответа человеком, очистка памяти диалога, группы — только выбранные.

Незнакомый номер получает только ответ агента: данные компании (сотрудники, заявки, суммы) в запрос к нейросети не передаются.

| Пункт | Значение |
|---|---|

| Версия схемы | `0007_access_and_kpi` (8 миграций, контрольные суммы в `db/migration-lock.json`) |
| Активация директора | Код владельца `OWNER_ACTIVATION_CODE` → страница `/owner` → одноразовая ссылка `/activate/…` → главная с «Первыми шагами». Повторная активация после регистрации директора запрещена |
| Серверные сценарии | `npm test`: 36 из 36 (доступ и изоляция, однократная активация, рабочие роли, перевыпуск приглашений, журнал прав, KPI сотрудника, дата начала, копирование, предпросмотр, прогноз, обучение и отметка «Прошёл обучение», CRM и конфликты, KPI = статистика, WhatsApp Studio: доступ директора, шифрование ключей, заявки из WhatsApp, очередь ответов на поддельных Whapi и ChatGPT) |
| Браузерные сценарии | `e2e/acceptance.mjs`, `stage1/2/3/5/7/8.mjs` на ПК и iPhone 13: пройдены, ошибок в консоли нет |
| Проверка артефакта | `npm run build` и `npm run test:artifact` (собранный Worker в Miniflare, миграции с нуля, WhatsApp Studio) |
| WhatsApp | Сборка готова. **Реальный обмен сообщениями через подключённый номер не подтверждён**: в среде разработки нет ключей Whapi/ChatGPT и выхода к ним в сеть |

Полный путь приёмки (`e2e/acceptance.mjs`): владелец выпускает ссылку → директор регистрируется, на главной — «Первые шаги» → создаёт филиал → приглашает руководителя → руководитель приглашает сотрудника → сотрудник на телефоне видит только обучение, проходит уроки и тест — рабочее место открывается само → создаёт заявку и переводит её в «Контакт» → руководитель на ПК видит её в статистике и открывает исходную сделку → директор на телефоне видит тот же показатель → руководитель другого филиала заявку не видит.

Чтобы подтвердить WhatsApp на опубликованном сайте: директор открывает WhatsApp Studio, создаёт агента, вставляет ключ WhatsApp (из кабинета Whapi, номер авторизован по QR) и ключ ChatGPT, добавляет файлы в базу знаний, проверяет ответы в «Проверить», включает агента и пишет на номер с другого телефона. В «Пользователях» появится собеседник, в CRM — новая заявка.
