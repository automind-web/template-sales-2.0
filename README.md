# AI Sales Corp

Шаблонный корпоративный сайт продаж для ChatGPT Sites (Cloudflare Worker + D1 + R2). Пять разделов на общей базе: Обучение, CRM, KPI, Статистика, WhatsApp Studio.

Публикация, привязки, миграции, секреты и активация директора описаны в **[README_SITES.md](README_SITES.md)**.

## Структура

```text
app/, components/     страницы и интерфейс (App Router на vinext)
  app/api/[...path]   единая точка API → server/router.ts
components/ui/        компоненты в стиле shadcn/ui
components/wa-studio/ интерфейс WhatsApp Studio
server/               серверные операции, сессии, проверка прав (access.ts)
  wa/                 движок WhatsApp Studio (из WhatsApp Agent Studio) и вход /api/wa
  handlers/           обработчики API по разделам
db/schema.ts          схема БД (Drizzle)
drizzle/              SQL-миграции (не правятся после применения)
config/company.ts     название, логотип, палитра, шрифты, плотность, воронка, правила допуска
i18n/ru.ts            все тексты интерфейса и сервера (kk/en добавляются рядом)
lib/hotkeys.ts        единый список горячих клавиш
worker/index.ts       вход Worker'а
.openai/hosting.json  привязки DB и BUCKET
test/                 серверные сценарии на node:sqlite (эмуляция D1)
e2e/                  браузерные сценарии (Playwright)
```

## Разработка

```bash
npm ci
cp .env.example .dev.vars   # заполните OWNER_ACTIVATION_CODE
npm run dev                 # http://localhost:5173, локальная D1 в .wrangler/state
npm test
npm run build
```

## Интерфейс

Оформление и расположение экранов повторяют систему AI Management; интерфейс сделан как приложение для обычного пользователя — без технических терминов, всё настраивается на самом сайте.

- **Главная** — сводка системы по роли: приветствие, новые заявки, заявки в работе, просроченные контакты, сделки за месяц (тем же расчётом, что KPI и статистика), дела на сегодня, обучение команды, состояние WhatsApp-агента; у нового директора — «Первые шаги».
- **Меню на ПК** слева: разделы с иконками, отметка просроченных контактов у CRM, индикатор работы WhatsApp-агента, внизу «Настройки системы» и карточка пользователя (профиль). Новому сотруднику до теста CRM и KPI показаны с замком.
  - Кнопка рядом с названием компании (или **Ctrl+B**, на Mac **⌘+B**) сворачивает меню до значков; при наведении на значок видно название. Выбор запоминается в браузере и восстанавливается без мигания.
- **Меню на телефоне** — нижняя панель вкладок, как в мобильных приложениях: значок и короткая подпись, активная вкладка подсвечена, отметки просрочек и работы агента на значках. Если разделов не больше пяти (например, у сотрудника) — все они на панели; иначе четыре главных (Главная, CRM, KPI, Статистика) и «Ещё» с остальными разделами, настройками и профилем. Панель учитывает полоску жестов iPhone, содержимое страниц под ней не прячется.
- Шапка страницы: заголовок слева, филиал справа (у директора — список с «Все филиалы»).
- Мягкое появление страниц и блоков, плавные счётчики, плитки с подъёмом при наведении (отключается при «уменьшить движение» в системе).
- Страницы входа — фирменная панель с разделами системы и форма.

Компоненты лежат в `components/ui`, цвета — в `config/company.ts` (`palette`).

## Роли и права

| Роль | Доступно |
|---|---|
| Новый сотрудник (до теста) | Только обучение и профиль; CRM и KPI видны в меню закрытыми |
| Сотрудник (обучение пройдено) | Главная, CRM, личный KPI, обучение, профиль |
| Руководитель филиала | Свой филиал: главная, обучение команды с отметкой «Прошёл обучение», CRM, KPI, статистика; в «Настройках системы» — сотрудники (с рабочей ролью), приглашения и журнал прав своего филиала |
| Директор | Вся компания: всё выше, программа обучения, WhatsApp Studio (ключи подключений — только у директора). «Настройки системы»: компания, филиалы, сотрудники, приглашения, рабочие роли, воронка продаж, журнал прав |

**Рабочие роли** (должности, например «Оператор» или «Стажёр») директор создаёт в «Настройках системы» → «Рабочие роли» и отмечает, какие разделы открыты: CRM, KPI, Статистика. Руководитель или директор назначает роль человеку в списке сотрудников. Роль только сужает права основной роли и на директора не действует; роль в архиве ничего не ограничивает.

Права проверяются на сервере при каждом запросе (`server/access.ts`). Роль, филиал, рабочая роль и отметка об обучении читаются из БД заново, поэтому изменения действуют со следующего запроса. Все изменения прав (приглашения и их перевыпуск, регистрации, смена роли, филиала и рабочей роли, отключение, коды восстановления, отметка «Прошёл обучение») видны в «Журнале прав».
